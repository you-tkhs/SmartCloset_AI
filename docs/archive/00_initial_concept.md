# 名前

SmartCloset AI

# 目的

**↓普遍的な動機**

- 【認知の課題】「クローゼットのブラックボックス化」

  多くの人が衣替えのたびに「こんな服持っていたっけ？」と気づく。手持ちの服を把握しきれていないため、似たような服を二重に購入してしまう経済的・環境的ロスが発生している。

- 【選択の課題】「決断疲れ（Decision Fatigue）」と時間コスト

  朝の限られた時間の中で、「今日の気温」「予定（オフィス、デート、雨天など）」「自分の気分」の3つの変数を満たすコーディネートをゼロから考えるのは、脳に大きな負担（決断疲れ）を与え、時間を浪費させている。

- 【技術の壁】「既存の管理アプリの入力が面倒すぎる」

  1. 既存のクローゼット管理アプリは、撮影による入力のあと、ユーザーが手動で「ブランド名」「色」「カテゴリ」を細かく入力し、背景を綺麗に撮影しなければならず、**管理を始める前に挫折する**という課題があった。
  2. 既存のアプリケーションによる自動コーデは、タグや気温のマッチングによるシステム的なレコメンドに過ぎず、自身の思いを反映させたコーディネートはできなかった。

---

# 既存アプリ(xzなど)との差別化

1. **LLMによる完全な個別最適化**

   XZのような先行アプリは気温と服のカテゴリの組み合わせが中心ですが、本アプリは**LLMの高度な文脈理解**を活用しています。ユーザーの「カレンダーの予定」や「その日の気分」といったテキスト入力（プロンプト）を環境情報（天気・気温）と掛け合わせることで、既存アプリにはできなかった「状況と心理に寄り添う、パーソナライズされたスタイリング提案」を実現しました。

2. **CVモデルによる圧倒的な登録体験**

   既存アプリで最もユーザーが挫折するのは「服の登録が面倒」という点です。どんな背景でも衣服の輪郭をピクセル単位で一瞬で完璧に切り出し、自動でメタデータ化（色・形・柄の抽出）を行うため、既存アプリを超える圧倒的にスムーズなUXを提供できます。

**↓個人的な動機**

- 自分が持っているたくさんの衣服の中から、自分の気分やその日の気温や予定における最適なコーディネートを選択するのが面倒くさかった。
- 久々にクローゼットを開けると「こんな服持ってたっけ？」となる時が多く、自分の手持ちの服を容易く管理したいと考えたから。
- 自身が培ってきた松尾研の講座で培ってきた「セグメンテーションの知見」・「LLMの知見」を活かしたアプリケーションを世の中に届けたかった。

# 動作(技術スタック)

- 自分が持っている衣服を写真で撮ると、自動で背景を切り出し(インスタンスセグメンテーション)、カテゴリ[Tシャツ、ジーンズなど]や色[黒、ベージュなど]・柄[無地、ストライプ]など判別(物体認識)。その後システムが自動でデータベースに書き込む。
- 自身が持っている衣服をいつでもクローゼットとして閲覧することができる。
- 自分の予定や気持ちなどを自然言語として入力すると、気温とクローゼットの中身を考慮して最適な衣服を自動で選出する。

# 制約

- 衣類の登録の際に時間をかけないようにする。
- はじめはオープンソースのAIライブラリを用いる。その後、精度が悪ければ自身でアノテーションとファインチューニングを行う。

### ・非同期タスクキュー（Celery ＋ Redis / FastAPI Background Tasks）の導入

画像処理（YOLOによるセグメンテーション ＋ 特徴抽出）は、CPUサーバーで動かすとどうしても1〜3秒ほどの時間がかかります。これをWebサーバー（FastAPIなど）のメイン処理の中で同期的に行うと、処理中にユーザーの画面がフリーズし、サーバーの接続上限にも達してしまいます。

**実装の工夫：**
ユーザーが画像をアップロードした瞬間、サーバーは「アップロード完了（ステータス：処理中）」というレスポンスだけを**ミリ秒単位で即座に返し、ユーザー画面を次に進めます**。
重いAI処理（セグメンテーションやDB書き込み）はバックグラウンドで非同期に実行させ、完了したら画面側のクローゼット一覧に「シュッ」と自動反映されるようにします。

### ・フロントエンドでの超高速プレビューとリサイズ

スマホで撮った生の写真は、ファイルサイズが数MB〜十数MBあり、ネットワークの通信だけで時間がかかります。

**実装の工夫：**
アップロードする前に、フロントエンド（JavaScript / Next.jsなど）側で、AIモデルが要求するサイズ（例：640×640ピクセルなど）に**画像を圧縮・リサイズしてからサーバーに送信**します。これにより、通信時間を劇的に削減し、バックエンドでの画像処理の負荷も最小限に抑えられます。

# 設計手順

### ステップ1：AIロジックの検証（Pythonスクリプト）

Webアプリを作る前に、まずはJupyter NotebookやローカルのPythonスクリプトで、画像処理のパイプラインを完成させます。

- 入力：適当に撮った服の写真
- 出力：背景が切り抜かれた画像 ＋ [カテゴリ, 色, 柄]のテキストデータ
- **アドバイス：** 松尾研での知見を活かし、YOLO（YOLOv8-segやYOLOv11-seg）のプリトレインモデルを試す、あるいは少量のデータで服のカテゴリ分類をファイントゥーニング（あるいは数ショット学習）します。

### ステップ2：バックエンドAPI ＋ DBの構築（FastAPI等）

ステップ1のロジックを、Webから叩けるAPIにします。

- **POST /items/upload**：画像を受け取り、非同期で画像処理を実行。結果をデータベース（SQLAlchemy等経由）に保存。
- **GET /items**：登録された衣服データの一覧を返す。
- **POST /coordinate/suggest**：ユーザーの「今日の気分や予定」のテキストと、現在の気温（天気API）を受け取り、DBの衣服リストをプロンプトに結合してLLM API（Gemini等）を叩き、提案テキストを返す。

### ステップ3：フロントエンドの結合（Next.js / React等）

最後に、ユーザーが触る画面を作ってAPIと接続します。

- ドラッグ＆ドロップ（またはカメラ起動）で写真を送る画面。
- 登録された服が、背景透過された状態で綺麗に並ぶ「マイクローゼット」画面。
- チャットボット風、あるいは1行の入力欄から「今日は大事な会議があるからカチッとしたい」と入力すると、おすすめの服の画像がハイライトされてLLMの解説コメントが表示される画面。
